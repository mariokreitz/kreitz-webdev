# Security (apps/api)

- **Dual auth scheme.** `@thallesp/nestjs-better-auth` registers a global `AuthGuard` by default (every route requires a valid Better Auth session cookie unless explicitly opted out) via `BetterAuthNestModule.forRootAsync` in `apps/api/src/core/auth/auth.module.ts:17` — no `disableGlobalAuthGuard` is set, so the package default applies. First-party/dashboard routes rely on this and read the session with `@Session() session: UserSession` (`apps/api/src/modules/website/website.controller.ts:3,20`). Machine/embed routes instead use `@AllowAnonymous()` to bypass the global guard and are protected by `WebsiteTokenGuard` + `ArcjetRateLimitGuard` (`apps/api/src/modules/public-projects/public-project.controller.ts:8,15-16`) — a bearer website token looked up by hash, never compared raw, plus an Origin-header check against verified website domains (`validateOrigin`, `apps/api/src/common/guards/website-token.guard.ts:126-165`) that's specific to the website-token flow, not a general CORS substitute.
- **Rate limiting is Arcjet only** (`@arcjet/nest`) — no `ThrottlerModule`, no hand-rolled limiter. Two independent integration points, each owning its own buckets: `ArcjetAuthMiddleware` (`apps/api/src/core/auth/middlewares/arcjet-auth.middleware.ts`) guards only `/api/auth/*`, with tighter/bot-detecting buckets on sign-up (5/min + email validation) and sign-in (10/min); `ArcjetRateLimitGuard` (`apps/api/src/common/guards/arcjet-rate-limit.guard.ts`) guards arbitrary routes, bucketed by `websiteId` when the request carries one (set by `WebsiteTokenGuard`) or IP otherwise. Both derive `mode: 'DRY_RUN' | 'LIVE'` from `app.env === 'development'` and both **fail open** on Arcjet errors — that's a deliberate choice, not a bug; don't "fix" it into fail-closed without a driving requirement.
- **`ValidationPipe` is global and strict** (`apps/api/src/bootstrap/app.boostrap.ts:141-150`): `whitelist`, `forbidNonWhitelisted`, `forbidUnknownValues` all `true`, `transform: true` with `enableImplicitConversion: false` — DTOs must declare the exact type `class-transformer` can produce; don't lean on implicit coercion. `disableErrorMessages` is production-only, so validation error detail is intentionally dev-only.
- **CORS is allow-list, off by default.** `applyCors` (`app.boostrap.ts:126-138`) only calls `enableCors` when `CORS_ORIGINS` is non-empty — an empty list means CORS stays fully disabled, not wildcarded. Configure the allow-list via `CORS_ORIGINS`/`CORS_CREDENTIALS` (`apps/api/src/config/security.config.ts`).
- **Two separate trusted-proxy configs — don't conflate them.** `TRUST_PROXY`/`PROXY_HOPS` (`security.config.ts`) control Express's own `trust proxy` setting (`hardenExpressInstance`, `app.boostrap.ts:44-51`). `ARCJET_TRUSTED_PROXIES` (`apps/api/src/config/arcjet.config.ts`, validated as IPv4/IPv6/CIDR in `apps/api/src/config/schemas/arcjet.schema.ts`) is a distinct value fed both into Arcjet's own client and into Better Auth's `advanced.ipAddress.trustedProxies` (`apps/api/src/core/auth/strategies/auth.factory.ts:68`) so Arcjet and Better Auth agree on the real client IP.
- **Helmet CSP is deny-by-default globally** (`defaultSrc: ["'none'"]`, `app.boostrap.ts:73-90`), with one narrow route-scoped exception for the Scalar/OpenAPI reference UI (`applyAuthReferenceCsp`, lines 92-116), gated behind `security.enableSwagger` and using a per-app nonce (`AUTH_REFERENCE_CSP_NONCE`) — don't loosen the global policy for a single route's needs, scope a new exception the same way instead. HSTS is production-only.
- **All env config is Zod-validated, parsed eagerly at module registration** — every `*.config.ts` calls `<schema>.parse(process.env)` inside its `registerAs` factory (e.g. `securityConfig`, `security.config.ts:5`), so an invalid/missing secret throws at boot, not at first use. Secrets carry real constraints, not just presence checks (`COOKIE_SECRET: z.string().min(32)`, `apps/api/src/config/schemas/security.schema.ts:17`). Never read `process.env` directly outside a schema.
- **Body size limits are layered.** Global `BODY_LIMIT` (default `100kb`, `security.config.ts`) applies to Better Auth's own body parser (`auth.module.ts:56-59`); the Arcjet auth-middleware's own pre-parse (to extract `email` for sign-up validation) uses a separate, tighter fixed `20kb` limit (`arcjet-auth.middleware.ts:21`) — these limits are independent, don't assume changing one changes the other.
