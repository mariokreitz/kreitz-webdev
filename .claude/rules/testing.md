# Testing (apps/api)

- **Direct instantiation, never `Test.createTestingModule`.** Every spec builds the class under test with `new` and hand-built mocks, not Nest's DI container — see `apps/api/src/modules/github-import/__tests__/github-import.service.spec.ts:82-117` and `apps/api/src/common/guards/__tests__/arcjet-rate-limit.guard.spec.ts`. `@nestjs/testing` and `supertest` are listed in the root `package.json` devDependencies but have zero call sites anywhere under `apps/` — that's an unused dependency, not a convention to adopt. This matches NestJS's own documented "isolated unit test" style (manual instantiation + `jest.spyOn`/mocked collaborators), not a repo-specific deviation from best practice; don't "fix" a spec onto `Test.createTestingModule` or a library like `@suites/unit`/`TestBed.solitary()` — neither is used here.
- **No e2e test app or config exists.** There is no `apps/api-e2e` project, no Playwright/supertest e2e harness, and no `*.e2e-spec.ts` file anywhere in the repo. `apps/api/jest.config.cts` is the only test config in the project, and the `test` target in `apps/api/project.json:46-50` carries no e2e-specific executor or options, just `passWithNoTests: true`. Don't invent an e2e setup unless explicitly asked to add one.
- **Build a local `buildLogger()` helper, mock only what the class under test calls.** `github-import.service.spec.ts:59-65,76-80` mocks exactly `setContext/info/warn` (what `GithubImportService` calls) as `MockedLogger`, then passes it to the constructor as `logger as unknown as PinoLogger`. `arcjet-rate-limit.guard.spec.ts:38-60` mocks the full `PinoLogger` surface as `MockedPinoLogger` (predates the minimal-surface convention) — prefer the minimal `MockedLogger` shape for new specs, not the full-surface one.
- **Mock external/hard-to-construct collaborators with a typed local interface, cast at the construction boundary.** e.g. `MockedGithubApiService`/`MockedProjectService` in `github-import.service.spec.ts:67-101`, each field a `jest.Mock<ReturnType, [ArgTypes]>`; the mock object is passed to the real constructor via `as unknown as <RealType>`. Repository interfaces (`IGithubAccountRepository`, etc.) use `jest.Mocked<Interface>` directly since they're already interfaces, no local mock type needed.
- **`@thallesp/nestjs-better-auth` is stubbed in Jest, not transformed.** `apps/api/jest.config.cts` remaps the whole package via `moduleNameMapper` (`^@thallesp/nestjs-better-auth$` → `apps/api/src/testing/mocks/thallesp-nestjs-better-auth.mock.ts`) because the real package is ESM-only (`import.meta.url`) and unparsable by CJS Jest. The stub exports exactly four names: `Session`, `AllowAnonymous` (no-op decorators), and empty marker classes `AuthModule`/`AuthService`. A spec needing `AuthService` behavior hand-builds and casts it (`github-import.service.spec.ts:104`, `{ api: { getAccessToken } } as unknown as AuthService`). Importing any other export from that package (e.g. `OptionalAuth`, `UserSession` as a value) will fail at import time until it's added to the stub file — that's the fix when a new spec hits it, not disabling the mapper.
- **Coverage is collected but not gating.** `collectCoverage: true` runs unconditionally with no `coverageThreshold` in `jest.config.cts` — a passing suite with low coverage is not a CI failure; don't add a threshold speculatively.
